# Handoff: payout accounts, VietQR and payment status (PR 3d)

## Endpoint changes
| Method | Path | Auth | Result |
|---|---|---|---|
| GET | `/api/banks` | public | `200 {"banks":[{"bin":"970436","name":"Vietcombank"},...]}`, cached 1 day. Banks that accept VietQR transfers. |
| GET | `/api/me/payout` | session | `200 {"bankBin","accountNumber","accountName"}` or `404 no_payout_account`; `private, no-store`. |
| PUT | `/api/me/payout` | session | Same body; `200` with the saved account. `422 {"error":"invalid_payout_account","field":"bankBin"\|"accountNumber"\|"accountName"}` (account number 6–19 digits; name `A–Z` and spaces, 2–50). |
| POST | `/api/matches` | session | New `422 {"error":"invalid_match","field":"payout"}` when `totalFeeVnd > 0` and the host has no payout account. |
| GET / POST | `/api/matches/{id}/slots/mine`, `/slots` | session | Joined view now adds `paymentCode`, `paymentStatus` (`awaiting_payment` / `payment_reported` / `confirmed`), `holdExpiresAt`, `amountVnd` (price × party size) and `payment` (`bankName`, `accountNumber`, `accountName`, `amountVnd`, `memo`, `qrPayload`) while money is still owed. |
| POST | `/api/matches/{id}/slots/mine/report-payment` | session | Stops the countdown (`payment_reported`); `200` with the joined view; idempotent; `409 not_joined`. |
| GET | `/api/matches/{id}/payments` | host | `200 {"parties":[{"paymentCode","team","holderName","guests","amountVnd","paymentStatus","holdExpiresAt"}]}`; `403 not_host`. |
| POST | `/api/matches/{id}/payments/{code}/confirm` | host | `204`; `403 not_host`; `404 party_not_found`. |
| POST | `/api/matches/{id}/payments/{code}/reject` | host | Releases the party; `204`; `409 already_confirmed`; `403`; `404`. |

Holds: a paid place is held for 30 minutes (`holdExpiresAt`); afterwards it disappears from the roster and can be taken again. Free matches and the host's own party are `confirmed` at once. Memo: `DAGHEP <paymentCode>`.

## Database changes
Migration `20261008000000_add_payments.sql`: `payout_accounts`; `slots.payment_status` and `slots.hold_expires_at` with a check that only `awaiting_payment` has an expiry. Existing slots become `confirmed`.

## Frontend actions
Done in this PR:
- `/account/payout` page with a bank list and the account name converted to uppercase without diacritics.
- `/create` shows a notice and blocks paid matches until a payout account exists.
- `PaymentPanel`: QR rendered in the browser with `qrcode`, copy buttons, "Tôi đã chuyển khoản".
- `HostPayments` on the match page, visible only to the host.
- An account-bar link to the payout page.
